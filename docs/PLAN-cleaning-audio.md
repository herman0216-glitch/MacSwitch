# MacSwitch：清洁模式与应用音量控制

## 方案结论

新增两项与截图风格一致的功能：**屏幕键盘清洁**、**音量控制**，沿用现有开关、排序、显隐和快捷键结构。

音量采用你确定的“父子关系”：**总输出带动应用，应用独立调整不改变总输出**。应用可自由设置 0～100，新出现时默认跟随当前系统音量。

需要保留一个明确边界：系统两项能准确同步 macOS 数值；应用高于系统输出时需要软件放大，**无法保证所有音源、设备下的 60% 都严格等同原生系统 60%**。应用百分比因此表示目标音量，受限时必须显示原因。

## 1. 屏幕键盘清洁

- 开启后关闭菜单面板，为所有显示器建立纯黑遮罩；屏幕保持点亮，不修改亮度设置。
- 每个屏幕中央显示清洁图标以及“退出清洁模式”按钮。鼠标可以移动，点击按钮退出；背景点击、滚动不穿透到其他应用。
- 通过 AppKit 窗口与主动键盘事件过滤拦截普通按键、组合键及可拦截的媒体键，同时暂停 MacSwitch 自身快捷键。Esc、空格、回车均不作为正常退出方式。
- 首次使用按需申请辅助功能权限；权限不足或拦截建立失败时不开启清洁模式。
- 正常操作只通过中央按钮退出；权限撤销、拦截失效、睡眠或应用终止时解除遮罩和输入拦截。电源键、强制关机及系统安全界面属于系统边界。
- 监听显示器连接变化；退出时恢复进入前的窗口呈现状态并释放防休眠资源。

## 2. 音量面板与联动规则

新增“音量控制”开关。开启后在该行下方展开控制区域，依次显示：

1. 提醒音量。
2. 输出音量及当前设备名称。
3. 正在输出声音的应用：图标、名称、滑块、百分比。

所有滑块范围为 0～100。面板内容超过可用高度时滚动，保留当前宽度及原生样式。

**联动规则固定如下：**

| 操作 | 行为 |
|---|---|
| 新应用开始播放 | 初始目标值等于当前输出音量，不改变原声音量 |
| 输出音量变化 `Δ` | 每个应用目标值变为 `clamp(原值＋Δ, 0, 100)` |
| 单独调整应用 | 只改变该应用；系统输出和其他应用不变 |
| 调整提醒音量 | 只写入系统提醒音量，不参与应用联动 |
| F10／系统静音 | 全部输出静音，保留滑块数值 |
| 系统输出为 0 | 全部无声；应用仍可保存目标值 |

例如：输出为 60，微信为 80，浏览器为 30；输出调至 90 后，两者变为 100、60；输出再降至 80，两者变为 90、50。触边后反向拖动立即参与联动。

控制中心、音量键和 MacSwitch 的输出调整统一执行上述规则；监听回读不得重复联动。提醒音量**数值**保持独立，但同一设备的实际提醒响度仍可能受系统总输出影响。

## 3. 音频实现与接口

- 保留现有静音服务，新增系统音量后端、应用音频发现服务、混音引擎及可观察状态模型；滑块连续更新单独处理，不塞进现有布尔开关命令队列。
- 系统输出与提醒音量读写真实系统设置，写入后回读，并同步外部修改。[Apple 系统音量命令](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_cmds.html)
- 应用音量使用 **Core Audio Process Tap → 私有聚合设备 → 增益处理 → 原输出设备**，采用 `mutedWhenTapped` 避免原声与处理后的声音重复播放。无需安装驱动或更改默认输出设备。[Apple Process Tap 说明](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)
- 请求系统音频录制权限，添加用途说明；音频仅在本机内存中处理，不保存、不上传。拒绝权限时保留系统两项控制，并明确显示应用音量不可用。
- 使用设备音量曲线计算应用目标与系统输出之间的补偿，避免重复降低音量。曲线无法获取时使用明确标注的近似映射。
- 默认补偿放大上限为 **＋12 dB**，增加平滑增益和峰值限制；达到限制时显示“放大受限”，不把目标百分比当作实际响度已达标。
- 按公开的进程、所属应用路径和 bundle ID 归并应用；浏览器按整个应用控制，首版不拆分标签页。排除 MacSwitch 自身音频，避免反馈循环。
- 首版接管当前默认输出设备上的单声道／立体声 PCM。其他输出路由、无法捕获或不支持的格式显示原因并保留原声，不强制转到扬声器。

关闭开关时收起面板、停止应用音频处理并恢复原声，保留用户当前系统音量。应用目标仅在本次启用期间保存；重新启用或重启后重新跟随系统。关闭菜单面板不会停止正在运行的混音。

## 4. 实施顺序与验收

**先验证底层能力，再接完整界面：**

1. 验证所有屏幕遮罩、真实键盘拦截和鼠标退出。
2. 完成系统两项音量读写，以及联动算法的独立测试。
3. 用两个同时播放的应用验证音频接管、独立调节、放大限制和原声恢复。
4. 接入面板、权限提示、设置兼容及完整生命周期，更新使用说明和验收记录。

**必要测试：**

- 联动：不同初值、触顶触底、反向拖动、快速拖动、外部音量变化、静音与零音量、回读去重。
- 清洁：真实键盘、媒体键、组合键、多显示器、全屏应用、显示器拔插、权限拒绝及异常退出；确认没有输入穿透。
- 声音：微信通话与浏览器直播同时播放；单独调节互不影响；新应用加入时声音不突变；比较同一音源在同一设备上的原生与应用刻度。
- 恢复：关闭功能、正常退出、强制结束、耳机断开、蓝牙通话模式切换、睡眠恢复后，无持续无声、重复播放或残留音频资源。
- 回归现有五项功能、排序、显隐、快捷键与旧配置加载。

目前已完成代码、SDK 和官方资料的只读核实，尚未实测新增功能。清洁输入拦截与应用混音必须分别取得实机证据；未通过的设备或内容不能列为已支持。
