# MacSwitch 首版开发计划

## 目标与交付

开发一款自己日常使用的 macOS 菜单栏工具，采用 **Xcode + SwiftUI**，借鉴 One Switch 的快捷操作方式，使用独立设计的现代原生界面。

已确定的默认范围：

- 支持 macOS 26 及以上，首版在你当前的 Apple Silicon Mac 上验收。
- 暂用名称 **MacSwitch**，界面使用简体中文。
- 菜单栏常驻，默认不显示 Dock 图标；设置使用独立窗口。
- 交付完整 Xcode 工程、本地 `.app`、构建运行脚本和使用说明。
- 第一阶段用于本机使用，商店上架、自动更新和公开发行以后再规划。

## 首版功能与界面

| 功能 | 首版行为 |
|---|---|
| 深色模式 | 切换系统当前深浅色，并同步系统外观变化。 |
| 隐藏桌面图标 | 隐藏和恢复桌面文件图标；先验证 Finder 偏好方案，不移动或删除文件。 |
| 防休眠 | 保持系统和屏幕不因闲置休眠；提供 30 分钟、1 小时、直到关闭，默认 30 分钟。 |
| 声音静音 | 控制当前默认输出设备，显示设备名称和实际静音状态。 |
| 麦克风静音 | 控制当前默认输入设备；设备不支持时明确显示原因。 |

菜单栏面板采用紧凑列表：左侧图标与名称，右侧原生开关，需要时显示设备名称、剩余时间或错误提示。底部提供设置和退出入口。

设置窗口包括：

- **通用**：登录启动，默认关闭。
- **开关**：逐项显示或隐藏、拖动排序；默认显示全部五项。
- **快捷键**：为每个功能录制全局快捷键，支持清除和冲突提示；默认不预占组合键。
- **关于**：版本和基本说明。

分辨率、台前调度、小组件、键盘清洁及蓝牙设备连接列入后续版本。

## 技术方案与开发顺序

**第一步：建立工程并验证系统能力。**

在当前 MacSwitch 目录建立 Swift 6 工程，交付可直接打开的 `.xcodeproj`。使用现有 XcodeGen 保持工程配置可复现，同时配置 Xcode 和 Codex 的运行入口。

优先验证桌面隐藏的真实效果、恢复过程和 Finder 刷新影响；同时验证系统外观切换、当前音频设备静音和防休眠释放。桌面隐藏必须通过实机验证，才能计入已完成功能。

**第二步：完成界面与功能连接。**

- 主界面使用 SwiftUI `MenuBarExtra` 的窗口样式及独立 `Settings` 场景。[Apple 菜单栏接口](https://developer.apple.com/documentation/swiftui/menubarextrastyle)
- 系统服务分别封装：外观使用 System Events，音频使用 CoreAudio，防休眠使用 IOKit；桌面兼容实现单独隔离。[音频静音属性](https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertymute)、[防休眠接口](https://developer.apple.com/documentation/iokit/1557078-iopmassertioncreatewithdescripti)
- 建立统一开关接口，提供能力检查、状态读取和异步切换；界面区分处理中、成功、失败、未授权和不支持。
- 切换后读取真实状态；失败恢复界面并显示原因。同一功能的连续操作串行处理。
- 使用系统通知和音频属性监听同步状态；打开面板时补充刷新。
- 全局快捷键使用系统热键注册接口，点击和快捷键共用同一执行逻辑。
- 排序、显隐及快捷键保存在本地。系统状态每次重新读取；音频设备切换后读取新设备状态，不自动继承上一设备的静音操作。
- 权限按功能首次使用时申请；拒绝授权只影响对应功能。

**第三步：完成日常使用与本地交付。**

加入登录启动、权限说明、错误恢复和版本信息。应用退出时释放防休眠；重新启动默认不开启防休眠。外观、桌面和音频保持用户最后设置的状态。

## 验收标准

- **工程**：Xcode 能直接构建运行；运行脚本可完成构建、启动和进程检查。
- **功能**：逐项验证真实系统效果、连续切换、外部修改后的状态同步和失败恢复。
- **桌面**：隐藏与恢复正确，文件保持原位；刷新失败时恢复原偏好。
- **音频**：当前输入、输出设备均实测；覆盖默认设备切换、设备断开和不支持控制的情况。麦克风效果需实际输入验证，单纯回读属性不足以验收。
- **防休眠**：倒计时、手动关闭、正常退出及异常退出后均正确释放。
- **权限与快捷键**：覆盖允许、拒绝、撤销授权，以及重复绑定和注册冲突。
- **界面**：验证深浅色、键盘操作、设置窗口显示、排序和重启后的配置保留。

自动测试负责状态流转、配置持久化、计时和错误处理；实机验收负责系统效果。交付说明分别记录已验证项目和仍受设备或权限限制的项目。
